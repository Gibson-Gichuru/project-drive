# ADR 0001 — Open mapping trial for Kenya

Date: 2026-11-13. Status: **trial implemented; final decision awaits field evidence**.

The project needs an Android map and route demonstration using open data, with no paid API, proprietary location service or public demo-server dependency. The workstation and owned K3s homelab have enough space and memory for a regional import.

Trial: use MapLibre Native to render OpenMapTiles generated by Planetiler from Geofabrik's Kenya OSM extract; serve the MBTiles and locally licensed Noto glyphs through Martin; obtain routes and turn instructions from Valhalla. Use the existing Go API as a private gateway that validates requests, limits payloads and returns provider-neutral route geometry/maneuvers. Keep renderer SDK types in its Android adapter and routing-specific types in the Go adapter. `NavigationEngine` and the REST contract stay replaceable.

This follows the specification's first routing candidate. OSRM and GraphHopper remain untested alternatives; no comparative quality claim is made. A public map-tile provider or public Nominatim endpoint is unnecessary. Coordinate/map-pin selection postpones a geocoder decision until address search is in scope.

The trial adds an offline data-build step, a separate persistent dataset, attribution obligations and two small serving processes. It does not deliver traffic-aware ETA, automatic rerouting, offline map packs or cross-border coverage. A phone route preview and simulated playback are distinct from actual GPS route following. The current component selection may change after Kenyan road observations and device/server measurements.

See [evaluation and measured build results](../navigation-evaluation.md), [data/dependency notices](../map-data-licenses.md), and the [M1 status](../milestones/M1.md). Accept this ADR finally only when the roadmap's M1 physical route gate and real-world road checks pass.
