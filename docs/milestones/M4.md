## Delivered behavior

The Android app now has Navigation and Convoy tabs around the same map. Convoy supports create (using the selected navigation endpoints), join by private invitation, open an existing trip, roster refresh, owner start/end/cancel, expiring invitation creation/revocation, owner removal and member leave. Destructive trip actions require a concrete confirmation. A prominent stop-sharing control remains available above the map while sharing. Navigation instructions keep their own space; setup and roster controls scroll. Do setup while parked or as a passenger.

Hilt supplies the repository, transport and Room database. OkHttp REST calls use Authorization headers, bounded responses, deadlines, no redirects, no response caching and generic errors. The native WebSocket handles server Ping/Pong, bounds its application channel to 16 messages, rejects binary/oversized protocol messages and bounds outgoing queued position bytes. Decoding requires a snapshot before deltas and uses instance/sequence ordering. Reconnect backs off from 1 to 30 seconds with bounded jitter, reauthorizes and clears cached markers until the new snapshot. Authorization/protocol failures stop sharing; normal transient transport failures reconnect only during the same foreground opt-in session.

Participant markers have a stable abbreviated ID matching the accessible roster, green/grey freshness styling and a geodesic accuracy area. The roster states reported accuracy and elapsed last-seen age. Freshness is anchored to monotonic receipt and server time using the earlier recorded/received time. Markers age without heartbeats and expire at the supplied TTL (default 30 seconds); stale begins at the supplied threshold (default 10 seconds). Disconnected state is labelled; reconnection never represents cached markers as current.

Location comes from Android LocationManager, without Play Services. Only real location callbacks enter the production sharing path. Publishing is throttled to at most one update per second and requires a fresh fix, positive accuracy no worse than 1000 m, current permission and an active foreground sharing session. Broader approximate fixes are withheld; approximate permission remains useful for the map. Guidance retains M1's stricter 50 m threshold. Preview playback is never sent as a real participant position.

## Consent, lifecycle and recovery

Sharing needs an active trip, location enabled in Navigation, and a separate disclosure/confirmation. Local navigation consent does not enable convoy publication. Stop-sharing, location-off and leaving the foreground immediately cancel publication/connection and clear markers. Rotation also stops convoy sharing; local navigation retains its existing rotation behavior. No foreground service or background-location permission is used because this increment shares only while the activity is visible. Background navigation/sharing is future work.

A Room revocation record is committed **before** enabling server sharing. It remains until share-off is acknowledged. An uncertain request, process kill or network loss cannot make the app silently resume sharing. On restart/reconnect while off, pending revocations are retried; no GPS collection or stream is restarted. Offline share-off cannot retract already delivered network bytes: server memory marks the previous fix stale and removes it within its TTL. Expired credentials may require importing a fresh session for the same user to finish server consent cleanup. Keep the pending record until that succeeds. A terminal/missing membership's 404 safely clears the journal.

Room version 1 holds selected trip IDs, pending revocations and invitation IDs/idempotency keys only. Future schema versions must add migrations and preserve the cleanup journal; destructive fallback is forbidden. It contains no coordinates, raw tracks, bearer tokens or invite secrets. Invite secrets live in memory and are hidden on background/share-off; the non-secret ID remains revocable after restart. A lost invite response can be retried with its saved request key to recover the ID for revocation. Session JSON is encrypted with an Android Keystore AES-GCM key into the app's no-backup directory; Android backup is disabled. Session claims are local hints only; the API always verifies the signature.

## Phase 0 local identity boundary

The debug app imports a short-lived offline-issued session using Android's document picker. The JSON shape is `{"token":"SHORT_LIVED_BEARER"}`. Never put the session in source, an APK asset, a shell argument, chat or logs. The import accepts at most 8 KiB. Delete the original plaintext session file after importing it; the app-owned copy is encrypted. Tokens and invitation codes do not belong in URLs. Release builds refuse the development import and do not get an authenticated development session.

Debug trip traffic uses `http://127.0.0.1:18082` through an explicitly selected ADB reverse to the isolated local API (workstation port 8080). Maps independently use the existing port 18081 homelab forward. Only debug loopback permits cleartext. Production transport/authentication remains a Phase 1 requirement; release convoy authentication is not claimed. The homelab continues rejecting development bearers with 401; never switch its APP_ENV to local/test.

For manual use, follow [M2 offline identity instructions](M2.md), configure the local API with the public verification key, mint a 15-minute token for each distinct test user, and import each token file privately on its device. Configure forwards:

```sh
adb -s "$ANDROID_SERIAL" reverse tcp:18082 tcp:8080
adb -s "$ANDROID_SERIAL" reverse tcp:18081 tcp:18081
```

Create a trip from the chosen navigation endpoints; create an invite; join from another signed-in device; owner starts the trip; each participant independently enables location and confirms sharing. The app must remain visible. A workstation-dependent reverse is a developer arrangement, not phone-only field connectivity or full offline operation.

## API endpoint gap fixed

Create/get/join/lifecycle responses now include nullable origin/destination objects. Create accepts both together with validated finite bounds and rejects partial/unknown coordinates. Android always supplies both. Legacy M2 clients may still omit both; existing rows stay nullable. Idempotency compares name **and both endpoints**, so a changed route cannot silently reuse a prior create. The existing PostGIS columns are used; no new migration or historical coordinate backfill is needed. Coordinates are selected trip endpoints deliberately persisted under the create disclosure, not live position history. Contract version is 0.5.0, preserving existing HTTP success codes.

## Reproduction and evidence

Build, unit-test and lint with `make ci`. Build the opt-in device test APK with:

```sh
cd apps/android
./gradlew --no-daemon :app:assembleDebug :app:assembleDebugAndroidTest
```

`ConvoySafetyTest` runs on Android and checks snapshot/sequence/freshness handling, transient restart versus terminal revocation, durable Room cleanup, encrypted credential round trips, rejected invalid imports and tamper rejection. Its credential test uses an isolated cache directory and never replaces a user session. `ConvoyDeviceTest` is skipped without a deliberately staged app-private fixture. The host checker creates offline identities in a private temporary directory, stages session bytes through ADB stdin, and never prints tokens or coordinates:

```sh
python3 scripts/android-convoy-check.py --phone "$ANDROID_SERIAL" \
  --second emulator-5554 --third emulator-5556
```

Run it against the disposable local Compose instance, with two booted emulators and the maps forward available. It temporarily configures that API's development verification key and restores the normal auth-disabled configuration afterward. It installs the debug/test APKs, uses fixed public synthetic points only at an instrumentation boundary on emulators, checks an initially unauthorized third client, and exercises stale/expiry, recovery, off, removal and lifecycle behavior. Synthetic inputs are not evidence of physical GPS movement. It stops test apps, removes staged fixtures and credentials, and preserves databases/volumes. Keep ordinary data out of this developer instance.

## Open-source dependencies

Hilt 2.60.1 and KSP 2.3.12 follow [Dagger's stable KSP setup](https://dagger.dev/dev-guide/ksp.html). Room 2.8.5 follows [the AndroidX release/setup documentation](https://developer.android.com/jetpack/androidx/releases/room). OkHttp 4.12.0 was already the renderer's resolved runtime dependency and is now declared directly for native REST/WebSocket use; see [the official repository](https://github.com/square/okhttp). These are open-source libraries, not hosted services or paid API dependencies. Dependency locks, SHA-256 verification metadata and the exported Room schema are committed.
