Status: **software implemented, verified, pushed and deployed on 2026-11-13. Physical

## Delivered

The Telemetry tab provides explicit local recording independent from navigation,
live sharing and manual upload. It reads native GPS and supported motion sensors,
saves derived distance/duration/speed/quality and candidate-event summaries, and
works without an account/network. The persistent finish button and screen-awake
flag apply only during capture. Foreground exit/rotation stops recording; durable
checkpoints recover as interrupted without restarting capture. Preview positions
are excluded. Unsupported sensors are tolerated.

[ADR 0002](../adr/0002-derived-telemetry.md) specifies the estimator, quality gates,
thresholds and limits. Candidates come from reliable GPS speed/course deltas;
IMU provides sensor presence/rotation context. This does not implement calibrated
IMU fusion, gravity removal, device-frame alignment or a driving score.

Only the last fix and a 120-entry/two-second raw sensor ring remain in RAM.
Room saves no coordinates or raw arrays: at most 20 recordings, seven-day summary
retention, detailed events capped at 100 and expired at 24 hours or upload ack.
A four-hour recording cap and five-second derived checkpoints bound work/recovery.
Counts survive omitted detail; quality and incomplete GPS coverage are visible.

Room migration 1 → 2 preserves M4's consent/revocation journal and trip selection.
API migration `0004_telemetry` adds private recording ownership, hashes, aggregate
JSON and event metadata; it never populates location columns. API contracts are
version 0.6.0. POST telemetry is bounded to 64 KiB; GET summary returns only the
caller's data. Upload requires active membership and active/completed trip state,
has stable UUID/hash retries and a 20-recording user/trip cap. Local binding before
request prevents ambiguous retry under a different trip/identity. Server retention
is seven days after upload, with expired reads excluded and minute-based deletion
cascading through event rows. Local delete and upload each require explicit UI
confirmation. No automatic upload, raw-track storage or third-party analytics.

The owner also requested public backend reachability during this milestone.
[The HTTPS runbook](../homelab-access.md) records the published Cloudflare route,
path restriction, Android defaults, checks and recovery. Maps/navigation work
without workstation forwarding. Development auth remains disabled on homelab;
private public features await production sign-in. A loopback API debug build is
required for development-session import, even if a previous encrypted session
exists. No paid service or new proprietary product dependency was introduced.

## Reproduction

`make ci` runs server tests/integration, migrations twice, vulnerability scanning,
Compose/Kustomize validation and default HTTPS Android build/unit/instrumentation
compilation/lint. For isolated emulator upload/process recovery acceptance:

```sh
cd apps/android
./gradlew --no-daemon \
  -PmapServerUrl=http://127.0.0.1:18081 \
  -PapiServerUrl=http://127.0.0.1:18082 \
  :app:assembleDebug :app:assembleDebugAndroidTest
cd ../..
python3 scripts/android-telemetry-check.py --emulator emulator-5554
```

Use disposable local Compose data and a booted emulator. The checker creates
short-lived identities in a private temporary directory, transmits credentials
through stdin, installs both APKs, revokes emulator GPS permissions for deterministic
synthetic fixes, and restores the local API configuration. It never installs a
synthetic GPS provider on a physical device. Failure logs stay under the owner's
private local state directory, outside Git.

Build default APKs again for public HTTPS use; follow the opt-in native network
check in the access runbook. Physical local recording can be tested offline;
map tiles/routes still need the server unless already loaded/cached. App background
recording, complete offline map packs, production sign-in, battery benchmarks and
field-calibrated telemetry remain future work or explicit validation gates.
