## Implemented

- Provider-neutral Android `NavigationEngine`, route/coordinate/maneuver types, route progress, and a remote adapter. MapLibre types are isolated in `map/MapLibreRenderer`.
- A self-hosted Kenya map built with Planetiler/OpenMapTiles and served with Martin, including locally served Noto glyphs and visible attribution. Valhalla supplies driving routes/instructions from the same OSM snapshot. No public tile/geocoding service or vendor key is used.
- Go gateway validates required coordinates and payload sizes, limits upstream time/response size, normalizes Valhalla geometry/maneuvers, and omits route bodies and tile identifiers from ordinary logs. The unauthenticated spike is rejected in production configuration.
- Android map-pin/coordinate destinations, route preview, explicitly simulated playback, manual GPS guidance, off-route/stale/accuracy states, explicit foreground location controls, and rotation state retention. GPS sharing, persistence and background collection remain absent.
- Repeatable build/package/upload scripts, checksummed immutable regional data releases, separate 10 GiB homelab PVC, read-only/nonroot map services, Compose overlay, OpenAPI contract, ADR/license/runbook documentation.
- CI now includes Android lint. GitHub publishing follows successful same-source CI and prevents older sources from replacing newer releases.

## Field preparation follow-up — 2026-11-13

The phone-only journey will use a route loaded before leaving the workstation connection. No public ingress or new mapping service has been added. New tiles and route calculations remain server-dependent; a cached route demonstration is not a full offline-maps claim.

Preparation changes: reject stale/out-of-order fixes; prefer a usable precise fix over an immediately interleaved coarse update for at most three seconds without extending its original timestamp; treat reported zero accuracy conservatively as unknown for guidance; round positive uncertainty up rather than truncating it to zero. Android permits zero as a reported accuracy, so this is a prototype quality policy, not a claim that Android's value is invalid. See [Android Location accuracy documentation](https://developer.android.com/reference/android/location/Location). Guidance/playback keep the foreground screen on using the [activity screen flag](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on); stopping restores normal timeout. Unavailable providers clear the current fix.

All eight Android unit tests, APK build and lint passed. The updated APK was installed through wireless ADB. The repeatable `scripts/android-navigation-check.py` passed default location-off, attribution, real self-hosted route preview, guidance refusal without a fix, labeled playback, awake-flag set/clear, server disconnect/reconnect, rotation, background/resume and process-restart checks. Only the fixed public sample was used. No GPS positions or screenshots were retained. Explicit runtime denial and location-off also passed. Coarse-only mode delivered no fresh fix within 35 seconds and remains unverified for actual fix delivery; original permissions were restored. The real journey remains pending; see [the device test record](../device-tests/2026-11-13-M1.md).
