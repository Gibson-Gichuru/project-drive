# Field test checklist — 14 November 2026 (Africa/Nairobi)

Status: **planned; no journey results recorded.** The owner deferred physical
journey testing until this date. No reminder or automatic test was scheduled.
M1 actual navigation, M4 two-real-phone convoy and M5 moving-phone telemetry gates
remain open. M6 also requires measured latency and 30–60 minute battery testing.

Use a short familiar public route and operate the app while safely parked or
through a passenger. Record public road/landmark names and approximate duration,
not home addresses or a private raw GPS trace. Mount the phone consistently.

1. Verify the installed APK uses the HTTPS origin in [homelab access](../homelab-access.md).
   With no ADB reverse/workstation forward, load a map and preview the selected
   route on Wi-Fi, then on mobile data. Confirm attribution and instructions.
   Record missing tiles, roads, incorrect one-way/access data or route failures.
2. While parked outdoors, enable location explicitly. Record displayed accuracy
   once 50 m or better. Choose **Start guidance**, not **Play preview**. During
   the journey check that real GPS advances the marker and instructions. After
   stopping record arrival/off-route behavior and route coverage observations.
3. In Telemetry, consent to **Start local recording**. No account is needed.
   Keep the app visible and avoid rotation during the main journey. After stopping,
   finish recording and record elapsed time, distance, GPS coverage, reported
   accuracy, estimated mean/max speed and candidate counts. Compare with approximate
   route distance/duration; do not deliberately brake/accelerate/corner harshly.
   These are uncalibrated estimates, not a safety/vehicle-performance score.
4. Check interruption while parked: rotation, Home/resume and process restart
   leave recording off and retain an interrupted summary. Offline local recording
   must remain usable; new routes/uncached map tiles still require network.
   Deleting a local summary requires confirmation and does not delete an uploaded
   server copy. No upload happens automatically.
5. Public homelab convoy/upload are currently gated on production sign-in, which
   is not part of M5. Do not enable development auth publicly to work around this.
   Private upload already has local Android/PostGIS software acceptance. Mark a
   public authenticated test pending until legitimate sign-in is implemented.
6. For M4's two-real-phone gate, obtain a second real phone and an authenticated
   test environment reachable by both. Separately consent on each phone. Check
   mutual positions, stale/expiry, network transition, share-off/removal/end and
   no silent restart. Emulators already supplied software participant acceptance,
   not this field result. Keep this gate deferred if only one phone is available.
7. M6: record device/OS, network and screen settings, start/end battery levels,
   elapsed 30–60 minutes, failures and thermal observations. Measure actual server
   receipt-to-broadcast p95 with sample count; network round trips or an app memory
   snapshot do not substitute for this measurement.

Afterward update M1/M4/M5/M6 with actual observed results, failures and remaining
gates. Never mark a planned or simulated check passed. Keep coordinate-bearing
screenshots and private device diagnostics out of Git and chat.
