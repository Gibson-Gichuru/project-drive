Status: **in progress, field gate open**. Recommendation and implementation spike started 2026-11-13. The selected trial is MapLibre Native Android 13.7.1 + Planetiler 0.10.2/OpenMapTiles + Martin 1.16.1 + Valhalla 3.9.1. Final selection requires the physical-device and real-world route gates below. ## Local route evidence

`scripts/navigation-smoke.py http://127.0.0.1:8080` passed against the built regional graph, checking nonempty geometry, valid maneuver indexes, distance/duration, a Nairobi vector tile and a Latin glyph range. Samples are fixed public map points, not device GPS.

| Sample | Graph distance | Estimated duration | Instructions |
| --- | --- | --- | --- |
| Nairobi CBD surface street to Langata Road | 4.4 km | 6 min | 14 |
| Nairobi to Ngong | 32.3 km | 29 min | 15 |
| Nakuru to Njoro | 19.4 km | 15 min | 12 |
| Mombasa to Nyali | 8.4 km | 11 min | 10 |
| Nyeri to Othaya | 19.0 km | 19 min | 9 |

These results prove the points connect in this graph. They do not prove the route is safe, legal, current or optimal in the real world. The original CBD origin beneath the elevated Expressway produced a 10.9 km route; the nearby surface-street origin produces 4.4 km. This is an important road-level snapping ambiguity to check in the field. Review one-way/access restrictions and elevated-road origin selection before accepting guidance.

## Device, connectivity and operational gate

- M0 startup/lifecycle checks passed on a real Android 17 Samsung phone over TLS wireless ADB; [report](device-tests/2026-11-13-M0.md).
- M1 Android build, eight route-progress/location-quality unit tests, and debug lint pass. Physical map rendering, route overlay, labeled playback, location permission, rotation and background/resume have device evidence in the M1 report; fresh GPS guidance and the field journey remain open.
- Initial M1 checks used loopback via `adb reverse`. On 2026-11-13 the owner authorized the existing Cloudflare tunnel's HTTPS app route; default builds now use that endpoint without workstation forwarding. The map/router Services remain private, production mode still rejects the M1 spike configuration, and development trip identity remains disabled on homelab. See [current access and public-path limits](homelab-access.md). Android cleartext is still restricted to debug loopback.
- Location is explicitly enabled, foreground-only, uses Android LocationManager and stops in the background. No proprietary location SDK, background permission, live sharing or raw GPS persistence is used. Origin/destination are sent to the self-hosted router only when requesting a route. Gateway tile identifiers and route bodies are excluded from ordinary logs; upstream request logging is suppressed.
- A loaded route is held in memory across rotation. A process restart resets guidance and location consent. Preview playback is labeled simulated and never supplies Android mock locations. Rerouting is manual; off-route, stale and inaccurate-location states must be assessed on-device.
- Full offline map packs are deferred. Existing cached tiles and a loaded route can remain, but new areas and route calculations need the server. Test failure/recovery of the private connection; do not claim offline navigation from a warm-cache demonstration.
- Address search/geocoding is deferred. Use coordinates or a long-pressed map destination. Evaluate a self-hosted geocoder before Phase 1 address search; no public Nominatim dependency is configured.
- Data storage is a separate operator-owned 10 GiB node-local PVC. Keep code/image rollbacks separate from dataset promotion. Retain the previous immutable data release for rollback and budget owned disk/network/CPU. No metered API or hosted map account is required.

## Reproduce and refresh

Use a new data directory for each snapshot. The initial auxiliary input downloads are over 1 GiB in addition to the Kenya PBF; keep at least 10 GiB free for build inputs, temporary files and release copies. The workstation build limits are explicit; homelab runtime limits total 1.5 GiB for tiles/router. An initial homelab idle snapshot during rollout reported API 2 MiB, Martin 9 MiB, and Valhalla 59 MiB with 1–2 millicores for the map/API processes. These are initial idle observations, not peak or field-load measurements; keep the stated limits as budgets.

```sh
export MAP_DATA_DIR="$HOME/.cache/project-drive/maps/new-snapshot"
scripts/build-kenya-maps.sh
MAP_DATA_DIR="$MAP_DATA_DIR" docker compose -f infra/compose.yaml -f infra/maps.compose.yaml --env-file .env up -d --build
scripts/navigation-smoke.py http://127.0.0.1:8080
export MAP_RELEASE_DIR="$HOME/.cache/project-drive/releases/kenya-YYYYMMDD-HASH"
scripts/package-map-data.sh
```

For a homelab update, first retain the current revision. Apply `deploy/homelab/bootstrap/map-data.yaml` with an authorized operator context (adjust its initial node selector for a different cluster). Upload using `scripts/upload-map-data.sh` with explicit `KUBECONFIG`, `MAP_RELEASE_DIR`, `MAP_RELEASE_ID`. It verifies every file before atomically renaming the new release. Set both map Deployment `subPath` entries to that immutable release ID, commit and push; CI must pass before the publish workflow updates the Flux branch. Verify the five sample routes through the homelab API, then delete only the import Pod. Keep the PVC and previous release.

To roll back, restore the previous image/deployment branch and previous dataset subPaths via a reviewed Git commit; never overwrite an archive currently in use. For a refresh, rebuild both components, repeat API and physical route checks, verify attribution/checksums, and promote the new immutable directory. Automatic data refresh is intentionally disabled for the spike.

## Field preparation retest — 2026-11-13

The updated Android build adds conservative accuracy handling, bounded preference for recent precise fixes, and an activity-only screen-awake flag during guidance/playback. Build, eight unit tests and lint passed. The repeatable physical-device stationary checklist passed against the homelab, including route preview, location-off guard, simulated playback, disconnected loaded-route behavior, route-request failure/recovery, rotation, background/resume and process restart. Runtime permission denial passed; coarse-only mode did not deliver a fresh fix within 35 seconds, so no coarse-fix success is claimed.

After the route smoke, observed resources were API 1m CPU/4 MiB, Martin 1m/11 MiB, Valhalla 2m/80 MiB, PostGIS 24m/31 MiB; phone app 321 MiB PSS. These are limited snapshots, not peak/battery benchmarks. Actual GPS route following still needs fresh suitable fixes and a real journey. The user selected phone-only testing: preload while connected, keep the app foreground, and expect new tiles/reroutes to require the workstation connection. See [the device record](device-tests/2026-11-13-M1.md). No full offline pack is implemented or claimed.
